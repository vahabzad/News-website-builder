5. تکنولوژی پروژه
==================================================

اگر پروژه موجود است:

- ساختار فعلی را بررسی کن.
- معماری آن را بی‌دلیل عوض نکن.
- Dependencyهای موجود را بررسی کن.

اگر تکنولوژی تعیین‌شده React است:

- React
- Vite

- از Create React App استفاده نکن.
- پروژه جدید را با Vite ایجاد کن.
- Routing استاندارد پیاده‌سازی کن.
- Environment Variables را اصولی مدیریت کن.
- ساختار پروژه قابل توسعه باشد.

اگر تکنولوژی سیستم Next.js است:

از ساختار استاندارد و مدرن Next.js استفاده کن و Vite را وارد پروژه نکن.

هیچ‌وقت React/Vite و Next.js را به شکل نادرست با یکدیگر ترکیب نکن.

9. تصاویر خبری و Visual Assets
==================================================

سایت خبری را بدون تصاویر خبری تحویل نده.

محتوای Mock باید Visual Asset داشته باشد.

به‌خصوص برای:

- Hero
- Featured News
- Category Cards
- Video Section
- Gallery
- Special Reports

تصاویر مناسب ایجاد یا استفاده کن.

اگر قابلیت Image Generation در محیط در دسترس است:

از آن برای تولید تصاویر Mock مرتبط با خبرها استفاده کن.

تصاویر تولیدشده را:

- در Assets پروژه ذخیره کن.
- واقعاً در UI استفاده کن.
- برای خبرهای مختلف تا حد ممکن تصاویر متفاوت ایجاد کن.

تصاویر باید متناسب با موضوع خبر باشند.

مثلاً:

اقتصاد → تصویر اقتصادی مرتبط

فناوری → تصویر تکنولوژی مرتبط

ورزش → تصویر ورزشی مرتبط

فرهنگ → تصویر فرهنگی مرتبط

سیاست → تصویر خبری خنثی و مرتبط

از تصاویر گمراه‌کننده یا نامرتبط استفاده نکن.

اگر Image Generation در دسترس نیست:

از Placeholderهای حرفه‌ای، موضوعی و قابل جایگزینی استفاده کن.

اما:

- Box خاکستری بزرگ
- فضای کاملاً خالی
- Gradient بی‌محتوا
- Hero بدون Visual

برای خبرهای اصلی قابل قبول نیست.

Aspect Ratio تصاویر را متناسب با محل نمایش تعیین کن.

از Layout Shift جلوگیری کن.

==================================================
12. Theme Priority
==================================================

مقدار colorScheme تعیین‌کننده Theme پیش‌فرض سایت است.

مثلاً اگر:

colorScheme = روشن

باشد:

سایت باید در اولین Load با Light Theme نمایش داده شود.

اگر Feature حالت شب نیز فعال باشد:

- Dark Mode قابلیت اختیاری کاربر است.
- Default Theme همچنان Light است.
- کاربر می‌تواند Theme را تغییر دهد.
- انتخاب کاربر ذخیره شود.

Feature "حالت شب" نباید مقدار colorScheme را Override کند.

اگر colorScheme = تیره باشد، عکس همین منطق اعمال شود.

21. Hero Section
==================================================

Hero را با دقت طراحی کن.

Hero یکی از مهم‌ترین قسمت‌های سایت است.

قوانین:

- خبر اصلی بیشترین Visual Priority را داشته باشد.
- اخبار جانبی واضح باشند.
- فضای خالی غیرعادی وجود نداشته باشد.
- Fixed Height غیرضروری ایجاد نکن.
- Card را صرفاً برای هم‌اندازه شدن با ستون دیگر کش نده.
- First Viewport باید اطلاعات مفید نمایش دهد.
- اگر محتوای یک Column کم است، Layout را تغییر بده.
- تصویر خبر اصلی باید نقش مهمی داشته باشد.

نمونه ساختارهای قابل استفاده:

A)
1 خبر اصلی + 2 یا 3 خبر جانبی

B)
1 Featured Story + ستون آخرین اخبار

C)
1 خبر اصلی + Grid چهار خبر

D)
2 خبر مهم + Headlines List

E)
Hero تصویری + Headlines

ساختار را بر اساس رسانه انتخاب کن.

مواردی مانند:

یک Card بسیار بزرگ + Card تقریباً خالی با همان ارتفاع

غیرقابل قبول است.

اگر بعداً در Screenshot فضای خالی غیرعادی مشاهده شد، Hero را بازطراحی کن.

اولین خروجی بصری را خروجی نهایی در نظر نگیر.

==================================================

آیا تصاویر کافی وجود دارند؟

آیا اخبار مهم سریع دیده می‌شوند؟

آیا Hero حرفه‌ای است؟

آیا Layout متعادل است؟

آیا Typography فارسی طبیعی است؟

آیا First Viewport مفید است؟

آیا رنگ‌بندی مطابق فرم است؟

آیا Theme پیش‌فرض صحیح است؟

آیا Logo واقعی وجود دارد؟

آیا تبلیغات جای منطقی دارند؟

آیا طراحی بیش از حد Generic یا AI-like است؟

هر پاسخ منفی را در صورت امکان اصلاح کن.
